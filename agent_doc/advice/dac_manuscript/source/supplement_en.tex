\section*{Supplementary Note S5: Gate observation and execution scope}

The current $n_l/n_b$ design disables gating. The following describes the historical numeric-token-quota extension, not a validated gate for unified L2. In unified L2, sink-boundary candidates can still yield far winners after ordinary far-page competition is removed. When the optional gate feature is disabled, ordinary far selection remains active; OFF denotes a calibrated per-layer skip decision only when the feature is enabled. The optional far-region gate observes a layer's prefill queries, stores a pending far-skip decision, freezes it at the first decode-path call, and reuses it until a new input clears the state (Supplementary Fig.~S3). That call can still consume question tokens, so it need not see the complete question. Calibration uses at most the final 256 available query rows, full-dimensional scores and per-query-head softmax; its averaged far-attention weight sum is compared strictly with the threshold. The threshold controls a prefill observation; it does not bound far-attention weight sum or task error during later decoding.



\textbf{Calibration geometry.} For sufficient history, let $S_c$ be the calibration length and $m_c=S_c-s-w$. The statistic sums attention over $[s,s+\lfloor(1-\alpha)m_c\rfloor)$ before averaging query rows and heads. The supported decode skip instead uses the historical page-aligned boundary $Bb_n$, where $L=\max(B,\lfloor\alpha(S-s-w)\rfloor)$ and $b_n=\max(\lfloor s/B\rfloor,\lfloor(S-w-L)/B\rfloor)$; its unprotected skipped interval begins at $s$. Even at equal lengths, these intervals need not coincide. With $B=64$, $s=4$, $w=128$ and $\alpha=.25$, their right endpoints are 6049 and 6016 at $S_c=S=8192$, but 703 and 704 at 1065. Thus the statistic is a proxy for far-region contribution, neither the exact mass of removed support nor a conservative bound on it. Protected prefix positions remain protected.

In the supported fixed-quota implementation (batch one, valid length and nonempty far history), OFF disables far competition and final unprotected far selection; it does not guarantee elimination of all far dot products, because a sink-edge page may remain eligible through boundary bypass. Unused L2 quota refills eligible near candidates without enlarging near's L1 page budget. Far-on, off-refill and off-no-refill are distinct interventions: removing far can change per-query softmax denominators and the aggregated near ranking. Consequently refill is not an isolated saving with an invariant near set. Preparation, quantization, repeat-to-float and S-wide buffers/softmax remain in the cost. The implementation does not support combining dynamic and static layer skipping. Batched state isolation, runtime state transitions and distribution-shift-triggered fallback have not been validated. Runtime adaptation of $\alpha,\beta,\gamma$ is outside the evaluated configuration.


This historical gate remains a separate candidate extension; its near-token refill rule does not apply to current unified L2. The archived gate task-level summaries do not identify generation-code revision, complete subspace flags or paired predictions, so they cannot validate this configuration. These implementation details qualify the mechanism rather than provide measured speed or quality gains.

\section*{Supplementary Note S7: Budgets and configuration identity}
\textbf{Current configuration and historical identities.} LoDA-SA uses explicit $n_l/n_b$, unified L2, 4/128 protection, dense prefill and sparse decode, with gating disabled; the illustrative, unvalidated compact point uses 32 near pages, a 4096-token near extent and a free-competition middle pool, with implementation defaults still 128/128. The E149 summary reports 4/128 protection but contains inconsistent page/token-quota labels; complete predictions and a reconciled execution identity are unavailable. At $K=1024$, disjoint protection leaves 892 nominal pooled middle slots, not a 320/572 or 640/252 regional split; those splits belong to historical numeric-token-quota configurations. The partial 64-token prefix page can reselect four protected positions, so distinct unprotected tokens are not guaranteed. The source interface currently requires \texttt{tli\_near\_tokens=off} alongside explicit near length and pages; zero or omission does not select this branch, and this compatibility sentinel is not a tunable token budget. StreamingLLM motivates small sinks but also reports benefits from longer semantic prefixes on LongBench; it establishes neither four-token optimality for Qwen3 nor a 128-token window. Changing 128/128 to 4/128 releases 124 retrieval slots at fixed $K$, confounding sink-length and retrieval-capacity effects. Historical representation scores, timing and protection diagnostics retain their own settings, not 4/128 labels.

\textbf{Integer boundaries and summary support.} In the current explicit-$n_l/n_b$ partitioned path, with $S=t+1$ valid cached positions including the current token and excluding padding, let $M=\max(0,S-s-w)$, $L=\max(B,n_l)$ and
\begin{align*}
b_n&=\max(\lfloor s/B\rfloor,\lfloor(S-w-L)/B\rfloor),\\
b_w&=\max(b_n,\lceil S/B\rceil-\max(1,\lfloor w/B\rfloor)).
\end{align*}
For sufficient history and disjoint protection, far and near L1 intervals before removing bypass pages are $[\lfloor s/B\rfloor,b_n)$ and $[b_n,b_w)$, respectively. The unified L2 interval is $[B\lfloor s/B\rfloor,S-w)$, with the combined page mask. Rounding and alignment can change near length from $n_l$. Summaries use full physical pages, not unprotected intersections: the partial prefix page includes protected keys, and the last near page can include recent-window keys at nonaligned $S$. Pooled L2 still stops at $S-w$. These rules exclude clustering, quota overrides and short-history branches.

\textbf{Scarce retained support.} In current unified selection, L1 page masking precedes L2 softmax. Pooled TopK clips counts to interval width, not positive support. If the clipped count exceeds that support, zero ties can select cached tokens from unselected pages; final selection does not reapply L1 eligibility. Fig.~S2 assumes sufficient support and disjoint protection; partial-prefix reselection is separate. Occurrence and quality effects in the reported runs remain unverified.

\textbf{Fair comparison.} Comparisons match model, input IDs, generation limits and task scorer; equal-$K$ sparse comparisons count protection within the final unique cap. Retain and report each method's native phase, layer and protection policies; policy-matched adapters are separate controlled comparisons. Internal page caps may differ, but construction, scoring, ranking and traffic count toward complete-request cost. Report realized token counts and selection granularity, and match hardware and precision for timing.

\textbf{Shared-subspace configuration LongBench settings.} The five experimental metadata files specify page size 64, L1 cap 128 pages, final cap 1024 tokens, compression ratio 4, tail coordinates, $\alpha=.25$, $\beta=.125$, $\gamma=.625$, near-average/far-minmax page scoring and 4-bit quantize--dequantize values. They specify shared KV-head selection, dense prefill and disabled static layer skip. All five execution records identify producer \texttt{35b39bd8\allowbreak{}e43cf478\allowbreak{}bb4f0ab6\allowbreak{}4a8457f0\allowbreak{}8d87c864}. For these non-projection runs, that tree gathers 32 coordinates for L1 but scatters quantize--dequantize values into zero-filled width-128 L2 keys and scores them with full-width queries. Thus 32/32 describes active coordinates, not both physical contraction widths. The later non-projection shared-subspace configuration path gathers width-32 Q/K for L2; the archived quality score does not directly validate that implementation. These implementation paths do not establish runtime execution or finite-precision ranking equivalence. The recorded tree also gives prefix protection $2\times64=128$, recent protection 128, and sparse decode on all Qwen3 attention layers. These code-derived fields do not certify an unrecorded modified worktree or an execution trace. The normal long-history allocation is 16/112 near/far pages and 640/128 middle tokens, plus 256 protected tokens. The 8192 candidate slots do not imply 8192 final attention tokens, nor bound L2 scoring: ordinary L2 scores the full history before masking. Realized per-step counts were not recorded.

The configured input cap is 31500 for these runs. Task sample counts and maximum generated tokens are: Qasper 200/128; HotpotQA 200/32; MuSiQue 200/32; GovReport 200/512; RepoBench-P 500/64. The cap is not an observed input length. The complete model/tokenizer revision, runtime precision, hardware identity and scorer revision are not established by these experimental metadata; they must be bound for a matched comparison. Document-cluster identity, a matched dense run and a predeclared task-quality tolerance are still required for non-inferiority testing.

\textbf{Nominal full-dimensional page-scoring variant.} Five legacy prediction files have no manifest or execution record. Filename/verdict records identify page 64, L1 cap 128, final cap 1024, compression ratio 4 and the same nominal $\alpha,\beta,\gamma$. Effective input cap, full implementation revision, protection, phase and complete scorer settings are not verified. Current defaults cannot fill these gaps.

\textbf{Nominal full-dimensional token-scoring variant.} Five manifests contain the same listed budget settings and an explicit full L2 flag. Four receipts omit the implementation commit. The MuSiQue receipt identifies \texttt{60027fba\allowbreak{}3672f337\allowbreak{}44917c4f\allowbreak{}59960d0f\allowbreak{}131f8ab0}, but that tree does not implement the recorded L2-mode field. The code actually executed is therefore not established by that commit. The nominal label and score are retained; full-dimensional L2 execution is not certified.

\textbf{Quest comparator.} The official evaluation uses dense multi-token prefill, sparse token-by-token processing, dense first two layers, and page selection per query head. Its 1024-token budget with chunk size 16 differs internally from 128 pages of size 64 in our selector. A controlled comparison aligns final unique $K$ and phase/layer policy, while reporting the page quotas and head-sharing distinction separately. A paper's native configuration and a controlled adapter must not be pooled into one result. No matched Quest or FullKV quality--request-cost result is claimed here.

\textbf{Other result families.} The synthetic 64K selector timings are single-layer, batch-one, single-query summaries with an unresolved sampling protocol (S6); they are not bound to the LongBench requests. Gate summaries identify thresholds but not complete implementation and subspace settings. Protection-only uses 256 tokens versus its reference's 1024. Missing identity, unknown gate/refill settings, and unmeasured complete costs remain unknown rather than being inferred from current defaults.

\textbf{Attribution controls (not completed here).} Fixed-index replay would compare representation reuse and reconstruction on identical decode inputs and horizons, counting preparation and maintenance. Per step, match coordinate maps, summaries, quantization, selected token indices and final-attention computation between arms. Separately vary only regional/global L1 allocation, fixing page size, $K_1$, representation, protection, unified L2 and its total budget and $K$. Both arms use the same history-wide page scorer; report shortages and realized page/token counts. Competitors need not share $K_1$. Historical gate/refill comparisons are separate from the current unified-L2 design; a future gate study must first define and verify its intended support semantics.

The preceding designs are requirements for future matched tests, not experiments reported in the main text.

\textbf{Representation maintenance and cost accounting.} Appended keys, moving regional boundaries and coordinate-map changes require consistent derived views, logical token indices and region assignments. The shared-map identity does not prescribe an incremental maintenance algorithm. Quantize--dequantize keys use 16 floating-point levels, not packed INT4 arithmetic. Complete-request timing includes representation preparation, maintenance, calibration, selection, KV gathers, attention and synchronization, counting overlapping work once. TTFT ends at the first returned token; TPOT averages subsequent return intervals. These definitions are requirements for a matched evaluation, not a claim that complete-request costs were measured in the archived studies.
