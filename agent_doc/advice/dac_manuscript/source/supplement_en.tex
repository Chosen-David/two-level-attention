\section*{Supplementary Note S5: Gate observation and execution scope}

When the optional gate feature is disabled, ordinary far selection remains active; OFF denotes a calibrated per-layer skip decision only when the feature is enabled. The optional far-region gate observes a layer's prefill queries, stores a pending far-skip decision, freezes it at the first decode-path call, and reuses it until a new input clears the state (Supplementary Fig.~S3). That call can still consume question tokens, so it need not see the complete question. Calibration uses at most the final 256 available query rows, full-dimensional scores and per-query-head softmax; its averaged far-attention weight sum is compared strictly with the threshold. The threshold controls a prefill observation; it does not bound far-attention weight sum or task error during later decoding.



In the supported fixed-quota implementation (batch one, valid length and nonempty far history), OFF skips far L1/L2 dot products and selection. Unused L2 quota refills eligible near candidates without enlarging near's L1 page budget. Far-on, off-refill and off-no-refill are distinct interventions: removing far can change per-query softmax denominators and the aggregated near ranking. Consequently refill is not an isolated saving with an invariant near set. Preparation, quantization, repeat-to-float and S-wide buffers/softmax remain in the cost. The implementation does not support combining dynamic and static layer skipping or applying the dynamic gate to Llama. Batched state isolation, runtime state transitions and distribution-shift-triggered fallback have not been validated. Runtime adaptation of $\alpha,\beta,\gamma$ is outside the evaluated configuration.


The main-text gate is a candidate extension to the shared-subspace method. The archived gate task-level summaries do not identify generation-code revision, complete subspace flags or paired predictions, so they cannot validate this configuration. These implementation details qualify the mechanism rather than provide measured speed or quality gains.

\section*{Supplementary Note S7: Budgets and configuration identity}
\textbf{Selected prefix/recent configuration.} The currently selected candidate uses four prefix tokens and a 128-token recent window, with dense prefill and sparse decode, while implementation defaults remain 128/128. The author-reported evaluation configuration (E149) explicitly selects 4/128; complete prediction and execution-identity records are unavailable. For sufficient disjoint history, protection is 132 and the nominal middle allocation is $1024-132=892$: near remains 640 and far receives 252. A four-token prefix occupies a partial 64-token page, so regional selection can reselect up to four protected prefix positions. The far quota therefore does not guarantee 252 distinct nonprotected tokens. StreamingLLM motivates small sink protection, but its LongBench comparison also shows that retaining a larger semantic prefix can help; it does not establish four as optimal for Qwen3 or validate a 128-token recent window. Compared with 128/128 at fixed $K$, this change releases 124 retrieval slots and cannot isolate the effect of fewer sink tokens. The archived five-task representation scores and historical timing/protection diagnostics retain their own settings; they are not relabeled as 4/128 results.

\textbf{Scarce retained support.} The sufficient-capacity example in Fig.~2b assumes enough positive-probability candidates in each region and disjoint protection; partial-page prefix reselection is accounted for separately. In the implementation, L1-masked logits become zero probabilities after softmax. Regional TopK clips its requested count to region width, not to the number of positive-probability candidates. If that support is too small, zero-probability masked positions may enter through ties. Thus page eligibility is the intended support, not an unconditional no-filler guarantee for every short or degenerate input. Actual selected counts and zero-tie behavior require explicit checks under scarce support.

\textbf{Fair comparison.} The sparse-comparator budget is the final unique attention support $K$, including protected tokens. L1 candidate pages are an internal design choice, not a quantity that must match a competitor. Their construction, scoring, ranking and memory traffic remain part of cost. Model, input IDs, generation limits, prefill/decode treatment, dense-layer policy and task scorer must be matched. Native and controlled-adapter results must be distinguished. Actual token counts after page rounding and selection granularity must accompany nominal $K$.

\textbf{Shared-subspace configuration LongBench settings.} The five experimental metadata files specify page size 64, L1 cap 128 pages, final cap 1024 tokens, compression ratio 4, tail coordinates, $\alpha=.25$, $\beta=.125$, $\gamma=.625$, near-average/far-minmax page scoring and 4-bit quantize--dequantize values. They specify shared KV-head selection, dense prefill and disabled static layer skip. All five execution records identify producer \texttt{35b39bd8\allowbreak{}e43cf478\allowbreak{}bb4f0ab6\allowbreak{}4a8457f0\allowbreak{}8d87c864}. For these non-projection runs, that tree gathers 32 coordinates for L1 but scatters quantize--dequantize values into zero-filled width-128 L2 keys and scores them with full-width queries. Thus 32/32 describes active coordinates, not both physical contraction widths. The later non-projection shared-subspace configuration path gathers width-32 Q/K for L2; the archived quality score does not directly validate that implementation. These implementation paths do not establish runtime execution or finite-precision ranking equivalence. The recorded tree also gives prefix protection $2\times64=128$, recent protection 128, and sparse decode on all Qwen3 attention layers. These code-derived fields do not certify an unrecorded modified worktree or an execution trace. The normal long-history allocation is 16/112 near/far pages and 640/128 middle tokens, plus 256 protected tokens. The 8192 candidate slots do not imply 8192 final attention tokens, nor bound L2 scoring: ordinary L2 scores the full history before masking. Realized per-step counts were not recorded.

The configured input cap is 31500 for these runs. Task sample counts and maximum generated tokens are: Qasper 200/128; HotpotQA 200/32; MuSiQue 200/32; GovReport 200/512; RepoBench-P 500/64. The cap is not an observed input length. The complete model/tokenizer revision, runtime precision, hardware identity and scorer revision are not established by these experimental metadata; they must be bound for a matched comparison. Document-cluster identity, a matched dense run and a predeclared task-quality tolerance are still required for non-inferiority testing.

\textbf{Nominal full-dimensional page-scoring variant.} Five legacy prediction files have no manifest or execution record. Filename/verdict records identify page 64, L1 cap 128, final cap 1024, compression ratio 4 and the same nominal $\alpha,\beta,\gamma$. Effective input cap, full implementation revision, protection, phase and complete scorer settings are not verified. Current defaults cannot fill these gaps.

\textbf{Nominal full-dimensional token-scoring variant.} Five manifests contain the same listed budget settings and an explicit full L2 flag. Four receipts omit the implementation commit. The MuSiQue receipt identifies \texttt{60027fba\allowbreak{}3672f337\allowbreak{}44917c4f\allowbreak{}59960d0f\allowbreak{}131f8ab0}, but that tree does not implement the recorded L2-mode field. The code actually executed is therefore not established by that commit. The nominal label and score are retained; full-dimensional L2 execution is not certified.

\textbf{Quest comparator.} The official evaluation uses dense multi-token prefill, sparse token-by-token processing, dense first two layers, and page selection per query head. Its 1024-token budget with chunk size 16 differs internally from 128 pages of size 64 in our selector. A controlled comparison aligns final unique $K$ and phase/layer policy, while reporting the page quotas and head-sharing distinction separately. A paper's native configuration and a controlled adapter must not be pooled into one result. No matched Quest or FullKV quality--request-cost result is claimed here.

\textbf{Other result families.} The synthetic 64K selector timings are single-layer, batch-one, single-query summaries with an unresolved sampling protocol (S6); they are not bound to the LongBench requests. Gate summaries identify thresholds but not complete implementation and subspace settings. Protection-only uses 256 tokens versus its reference's 1024. Missing identity, unknown gate/refill settings, and unmeasured complete costs remain unknown rather than being inferred from current defaults.

\textbf{Controls needed for mechanism attribution (not completed here).} Replay with fixed token indices isolates reuse cost by comparing reuse and reconstruction over the same decode horizon, including initial preparation and per-step maintenance, under the same coordinate map, summary and quantization rules, selected token indices and final attention. To isolate L1 regional allocation, the regional/global comparison instead fixes page size, total L1 cap $K_1$, representation, protection, L2 refinement and its token quotas, and final cap $K$; only L1 regional allocation changes. Both configurations use the same page scorer across the history, and any candidate shortage is reflected in realized token counts. These ablation controls do not require competing sparse methods to share $K_1$. Gate comparisons retain active far selection, far exclusion with near-quota reallocation, and far exclusion without reallocation because removing far can also change the near ranking.

The preceding designs are requirements for future matched tests, not experiments reported in the main text.

\textbf{Representation maintenance and cost accounting.} Appended keys, moving regional boundaries and coordinate-map changes require consistent derived views, logical token indices and region assignments. The shared-map identity does not prescribe an incremental maintenance algorithm. Quantize--dequantize keys use 16 floating-point levels, not packed INT4 arithmetic. Complete-request timing includes representation preparation, maintenance, calibration, selection, KV gathers, attention and synchronization, counting overlapping work once. TTFT ends at the first returned token; TPOT averages subsequent return intervals. These definitions are requirements for a matched evaluation, not a claim that complete-request costs were measured in the archived studies.
