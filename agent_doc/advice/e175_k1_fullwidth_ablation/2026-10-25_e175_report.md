# E175: K1=64 全宽 Attention 消融——L2 选择必要性判决

**日期**：2026-10-26
**机器**：pc40 GPU0 (NVIDIA H20-3e), Qwen3-8B bf16, commit 320097b
**状态**：COMPLETE — 24 臂全 rc=0，判决已出

---

## 1. 核心问题

K1=64 是当前 LoDA-SA 生产口径（iter3 链合入后主表 K1=64）。在 K1=64 下：

- K1 选中的全部 64 page × 64 token/page = **4096 token**（R_cap = K1×bs + 2×bs = 4224 候选）
- L2 从中精选 **K2=1024 token**（fine scoring + topk，开销 ~3.3ms/步）
- far_quota(64) = 448（**甜点**：far 充裕，无断供风险）

**消融问题**：如果跳过 L2 精选，对 K1 选中的全部 token 做**全量 attention**（K2=4096，覆盖 R_cap 的 96.8%），是否：
1. 质量不变甚至更优（多看到 token 不亏）？
2. 性能更优（省掉 L2 fine scoring+topk+gather ~3.3ms）？

---

## 2. 实验设计

### 三臂对比

| 臂 | 名称 | 几何 | 说明 |
|---|---|---|---|
| A | champion | K1=64, K2=1024, L2 精选 | 生产配置 |
| B | fullwidth | K1=64, K2=4096, 跳过 L2 | 对 K1 选中全量做 attn |
| D | dense | Full dense attention | Baseline |

所有臂共享冠军 flags（nb32/nl4096/nt448/minmax+avg/sink4+swa128/tail32/cmp_ratio4/layer_skip=false）。

### 协议

- **质量**：LongBench 五任务 × 30 样本（hotpotqa, musique, gov_report, qasper, repobench-p），每任务独立 metric（hotpotqa/musique/qasper=qa_f1, gov_report=rouge-l-f, repobench-p=code_sim/difflib）
- **性能**：e152v4_graph_latency graph-mode, warmup=1 + measured=3, max_gen=8, 三长度（32K/64K/128K）
- 关键环境变量：`TLI_E127_W_UPPER=4096`（让 K2=4096 在 32K 能走 gather 路径，4096×8=32768=T）

## 4. 判决

**REJECTED**。全宽 K2=4096 在 K1=64 下是**双输**方案：

1. **质量降**（宏平均 -0.98pt）：多跳 QA（hotpotqa、musique）退化 3-3.5pt。这两类是 far 敏感型任务（E140b 已证实 K1=256 时 far=0 会崩塌到 45/21pt）。
2. **性能降**（每步 +2.4ms / +13%）：省掉的 L2 选择（~3.3ms）被 4× 更宽的 gather+GEMM 完全抵消且有**余**。
3. **无 trade-off 空间**。

### L2 精选为什么是 net positive

- **节省 GEMM 宽度**：从 4096 降到 1024 = 4x 减少，节省 ~3.3ms
- **L2 选择成本**：fine scoring + topk + gather ≈ ~3.3ms
- **净效果**：-2.4ms（省） + 多跳质量 +3pt

L2 精选的**真正价值**不在速度，而在**多跳推理质量保持**——精确剔除远端低分 token 防止注意力稀释。

## 5. 跨实验一致性

| 实验 | 关键发现 | 与 E175 关系 |
|---|---|---|
| E140b | K1=256 → far=0 → hotpotqa 59.2→45.3 | far 配额机制：K1=64 是甜点，K1=256 归零 |
| E140h | K1=64-128 AVG5：hotpotqa/musique 敏感 | 全宽退化也在这两任务最严重 |
| E140_l1_dilution | K1=64 far_quota=448 甜点 | K1=64 时 far 充裕，全宽不是缺 far |
| E127_W_upper | W_upper×8>T 触发 dense fallback | 全宽需 TLI_E127_W_UPPER=4096 才跑得动 |
| E166d2 (iter3d) | iter3 消除 copy 蜂群，TPOT -2.5ms | E175 冠军 17.7ms 已是 iter3 后口径 |

**闭合链**：K1 小 → far 充裕 → 全量 attention 不增加 far 收益，但增加 GEMM 宽度税 + 丢失 L2 远端鉴别力 → 质量降 + 速度降。

**正文建议**：

> For K1=64, attending to all tokens in the selected K1 pages (K2=4096, bypassing L2 fine selection) degrades quality by -0.98pt AVG and slows decode by +2.4ms/step (+13%), as the saved L2 overhead (~3.3ms) is more than offset by 4x wider GEMM+gather. L2 selection is essential, not optional—its value lies in quality preservation on multi-hop reasoning tasks rather than speed.
