## 给 Opus：一个新质量臂，先验写清预算后果

请先只读检查现有宿主产物与实际在飞任务、卡占用；已有匹配点优先复验，勿重复派发。若确实缺失，在现有授权资源内补 E146c 的 **K512 一个臂**：Qwen3-8B、32K/no-YaRN、原11任务各100条与同一顺序/输入/答案/ID、官方 scorer 和生成协议全部冻结。冻结 α=.25、β=.125、γ=.625、page64、K1=128、cmp4、保护 sink4/SWA128、粗筛/细筛表示、gate 关闭、dense-prefill/稀疏-decode 阶段及 fallback、模型/tokenizer/config/精度/backend/cache 身份；以 E146c 实际回执为准，不从当前默认值补猜。唯一干预是最终预算 K1024→512。

K 是**含保护位置、去重后的最终逻辑 token 上限**，不是额外512，也不是512页或512粗筛候选；实际选中可少于上限。现代码在足够长序列、保护不重叠、无 oracle/配额 override 且 far 路径生效时：

| 参数推导（非实测） | K1024 | K512 |
| --- | ---: | ---: |
| L1 near/far 页（K1=128） | 16/112 | 16/112 |
| 扣保护后 Kmid | 892 | 380 |
| nominal near=min(16×64×.625,Kmid) | 640 | 380 |
| nominal far=Kmid−near | 252 | 0 |

因此这次降 K 同时令最终 far 配额归零，不能解释为区域支持不变的纯算量缩放；far 配额为零也不代表 far 预处理/打分成本为零。不要暗改 β、γ、K1 或 gate 来补救。运行前记录实际参数快照；运行中/独立审计记录真实去重总数、保护/near/far 数、因果可见范围、边界页、fallback 和物理 gather 工作量，区分逻辑上限与物理工作量，避免只凭 CLI 或平均预算验收。

质量主指标为固定11任务的等权 AVG，同时完整公开每任务差值、负向任务及样本数。以同一 task/sample ID 配对 K512−K1024，并对同协议外部参考给配对差值/95%区间；按任务分层，按真实独立生成单元重采样，配对臂共享重采样索引，固定种子与重复次数。若样本有共享来源依赖，使用可核验 cluster ID；不得虚构文档ID。原始预测、身份或覆盖缺失则配对结论 blocked；必要时由 Opus 提出匹配 K1024 补跑，不能擅自把历史摘要当配对原始数据。

现 `paired_quality.py` 是 LongBench 专用，拒绝 RULER，且限定臂名/模式；不可改标签硬喂。最小候选是给原生 RULER 官方逐样本评分与身份校验增加受限分析适配，保持 task AVG 估计量和真实重采样单元；先独审及普通/-O 的 CPU 正常/缺ID/重复ID/错身份/缺任务测试，再消费新结果。本建议没有实现该适配。

不要求每个任务零下降，也不事后设置“可接受损失”。未预先约定 AVG 非劣界限时只报告差值与不确定性；区间跨0不证明等效或非劣。两个 K 点不能证明全局最小 K。

## 给 Opus / DeepSeek：完整请求时延对照

Opus 负责我方 K512/K1024 与 dense 控制；DeepSeek 仅负责相关外部基线（优先该 AsyncTLS K512 点）的身份/预算/校准核对和同协议成本。请协调同一现有硬件、精度、软件/backend、batch/concurrency、固定请求列表与输出协议，避免同时同卡竞争；记录 live 任务/卡读回再决定排期，不以本文当成已启动任务。不要复活暂停动态线、取消的 MLA 研发或修改 SGLang；不新增付费资源。

最小计时样本列表在看时延前固定并均衡覆盖上述11任务，同一批请求交错/随机顺序重复跑各臂，公开逐请求与逐重复数据。主比较走真实 RULER 生成路径、相同 max-new-tokens/EOS/停止策略；记录实际输入/输出长度和终止原因。自然输出长度差异要公开，不能将早停当相同工作量；若另做定长诊断，单列且不替代主请求结果。

完整 E2E 边界为请求输入可用→最终文本输出可用，包含分词/H2D、每请求预处理、索引构建/维护、选择、gather、attention、必要同步与输出解码。报告同边界 TTFT、TTFT 后 TPOT（实际首 token 后数量为分母，0个则 NA）、连续 request wall 的中位数/尾部/配对区间与实际 n；计时端到端完成须同步，但避免主计时每步同步。TTFT 若只到 GPU token 而非对外文本，另标计算指标，不冒充相同边界。

分别报告 warm-serving、冷启动/冷索引及校准成本；模型加载是否纳入冷启动必须明示。外部校准/一次性索引准备不能藏在计时外：原始成本单列，并给 **(一次性成本 + N 次完整请求总成本)/N** 的明确 N 摊销，不能假设免费或无限摊销。诊断阶段计时可以另测，但不能拼接阶段中位数充当总时延，不能将仅 attention kernel、tokens/s 或 TPOT 替代完整 E2E。

现 E152 collector 固定 synthetic needle、手写生成循环、每步 sync，并排除 tokenizer/H2D/部分 cache 分配及文本输出；它能提供 model-entry wall 诊断，**尚不能直接跑上述完整请求协议**。最小待审改动是接冻结真实请求与生产生成入口、明确完整 start/end 与首输出事件、补准备/校准与冷暖状态元数据、分离低扰动主计时和逐步诊断；复用现原子输出与身份门禁，不另造平行计时体系。若入口/路由身份仍未核验，标 blocked，勿改名交付。修改由对应负责人在既有授权内独审、测试后开展；本文未改 collector。
