# task：主 AI 整合后的执行计划

这里是主 AI 将用户要求、人工指南、相关建议和已有证据整合思考后，为自己
及获分配的角色维护的任务入口。计划应解释如何完成真实需求，不能把 AI 自己
的猜测升级为人类要求。

- [TASK.md](TASK.md) 是唯一活跃总清单：按日期列稳定任务 ID、目标、状态
  和详情链接，由主 AI 串行维护。
- `task_details/<任务ID>.md` 保存各任务的方法、进度、证据、阻塞与下一步；
  每个文件只有一个负责写入的 AI。

主 AI 先按人工指南（sglang 根 TASK.md / 论文indexer.md）确定约束与优先级，
再对 advice 记录取舍，核查已有 results，明确依赖、负责人、交付物和验收。
每项人工要求都应关联任务，已采纳建议也应能追踪到落实位置。

每次收到结果后核对：属于哪个要求、实际产物在哪里、证据能支持什么、还有
什么未完成、由谁继续。只有满足对应验收后才勾选；失败、暂缓、取消和缺
证据应保留真实状态。

高频日志与运行状态放 `.agent-runs/<run_id>/`，不塞进 TASK.md；新数据和
验证记录放 [results](../results/README.md)。

## task_details 的分工

一个任务对应 `<任务ID>.md`，文件开头注明 `Task-ID` 和 `Date`。负责人维护
分配给自己的详情，其他角色提交反馈与证据，不抢写同一文件或另建总清单。

- `## Plan`：记录原始目标、人工约束、已采纳建议、方法、依赖、资源边界和
  验收标准。实质变化要明确版本与原因，重新核对受影响的执行和证据。
- `## Progress`：追加实际完成情况、产物路径、检查结果、失败、未知项、
  阻塞及下一步；区分计划做什么和实际做了什么。
