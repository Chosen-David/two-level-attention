## 0. 对比设计论证（核心：为什么比这些、比哪些指标）

### 0.1 论文创新点与设定（对比的出发点）

| 创新点 | 内容 |
|---|---|
| I1 两级索引 | L1 块级粗筛**分 near/far 双池**（minmax/avg/cluster/sim_greedy 可组合）+ L2 token 级细筛 |
| I2 预算配比 (α,β,γ) | α=near 比例、β=near 块预算、γ=L2 配额；**可解释、可调**（冠军配置可搜） |
| I3 正交强制区 | sink + swa 必选且**不占预算**（锚定 attention sink 与局部性） |
| I4 training-free | 无需微调/续训，直接跑预训练模型 |
| I5 方法族可组合 | far×near×聚类变体 → 海选出冠军 |

设定边界：decode 侧稀疏（非 prefill 压缩）；预算口径 K2=1024 等效 token；
主模型 Qwen3-8B，扩展 Qwen3-32B 与 DeepSeek-V2-Lite-Chat（MLA）。

### 0.2 创新点 → 竞品映射（应该对比谁）

| 我们的创新点 | 对位竞品 | 对位理由（审稿视角） |
|---|---|---|
| I1 两级索引 | **Quest**（ICML'24）、**ClusterKV**（DAC'25）、**MoBA** | 同为「预算型稀疏 decode」赛道，直接重合，必比 |
| I1 聚类语义（ccluster 族） | **ClusterKV** | 语义簇召回对位（我们 L1=cluster 时同思路） |
| I1 块级 gate（moba 臂） | **MoBA** | chunk gate 对位；MoBA 训练依赖 → training-free 下界对照 |
| I3 sink 强制区 | **StreamingLLM**（ICLR'24） | sink attention 同理念；StreamingLLM 是纯 sink 全局锚点设定 |
| I1+I4 预算/压缩效率 | **H2O**（ICLR'24）、**SnapKV**（ICLR'24）、**PyramidKV**、**Scissorhands** | KV 压缩赛道常被同表比较；KVCache-Factory 统一接入 |
| I4 training-free 对位 | **DSA**（2025，Meta）、SeerAttention（NeurIPS'24）、LazyLLM（ACL'24） | DSA 用**训练型轻量 MLP 直接预测 topk 位置**（训练换推理速度）——对位我们 I4 零训练卖点；LazyLLM 为 training-free 对照候选 |
| 长上下文鲁棒 | InfLLM / Longformer / MInference / MagicPIG（注记） | 不同设定（模块化/训练型/LSH），不进主表只注记 |
| dense 上界 | **FullKV** | 必报锚点（我们数据已有） |

### 0.3 对比指标（论文报哪些数）

1. **精度主表**（官方 scorer，同模型同数据同预算）：
   - LB v1：16 任务 + 平均（difflib）
   - LB v2：503 题 + 平均（choice 抽取）
   - RULER：32/64/128K 各任务 + 平均
2. **效率副表**：
   - kernel microbench：`benchmark/efficiency` 同台面（稀疏 vs dense 延迟/吞吐，32K/65K/128K）
   - e2e wall-clock（pred 入口）+ 选择器开销（metrics）
   - KV 显存：预算 K2 ↔ KV 规模（TLI 的减显存卖点）
3. **质量-预算 Pareto**：K2 ∈ {512,1024,2048} 精度曲线 → 展示 I2 可解释分配 vs 单级方法的取舍

### 0.4 基线分层（不是「clone 哪些就比哪些」）

| 层 | 基线 | 进表 | 接入方式 |
|---|---|---|---|
| **T1 必比**（同赛道） | Quest / ClusterKV / MoBA | 主表全量 | A 轨公平实现 + **B 轨 vendor 源码双证**（用户 18:2X 开源复现指令） |
| **T2 应比**（KV 压缩/长上下文） | H2O / SnapKV / StreamingLLM / PyramidKV / Scissorhands / **DSA** | 附录或效率对照 | **KVCache-Factory 统一 harness**（已有 16 方法接入，run_longbench.py/run_ruler.py）；DSA 按 vendor 源码单独接（训练型，标注训练开销） |
| **T3 注记**（训练型/不同设定） | Mistral SWA / Longformer / 续训 MoBA / InfLLM / SeerAttention / MInference / MagicPIG | 论文引用 + 口径说明，不复现 | — |

说明（2026-10-11 用户追加）：**DSA 必须列候选**——它同为「预算型稀疏 attention」，是审稿人最可能追问的新竞品。与 Quest 的本质区别：**Quest/TLI 的选择由推理时实时 qk score 产生（零额外参数，training-free）**，而 **DSA 的选择由一个训练过的轻量 MLP 预测**（MLP 无论标签来源都需训练阶段拟合）→ 归 training-aware，作「训练型稀疏」对照，标注训练开销（T2）；其 Qwen3 可复现性评估见 §3.5，可行则 B 轨，否则 T3 注记。

选择依据 = 论文主张边界（training-free、decode 稀疏、预算型）× 审稿人最可能质疑的竞品。
主表控制篇幅：T1 全量 + FullKV 锚点；T2 进附录/效率对照；T3 只注记。

## 3. 复现思路（T1 三基线 × 模型）

### Quest
- 官方 `evaluation/quest_attention.py` 只支持 Llama/Mistral → `qwen3_quest_patch.py`
  移植 Qwen3Attention（字段层_idx/groups/head_dim 齐全，工作量小）；超参
  token_budget=1024 / chunk_size=16 对齐论文。
- kernel 线依赖 libraft（子模块缺失）→ 精度走纯 PyTorch；性能引用官方论文 + 平台差注记。
- **MLA 不适配**（GQA 假设）→ DeepSeek 档注记 + 论文引用。

### MoBA
- `moba/` 4 文件，`register_moba(MoBAConfig)` 注册 backend；预算 topk=budget/chunk
  （chunk=64, topk=16/32，与 E89 臂一致）。
- **training-free 下界对照**（官方自述需续训）——论文措辞：MoBA 为训练依赖方法，
  training-free 下以其官方实现复现作下界。
- decode paged attn 官方 TODO → 长生成慢速路径，不改（对方工程债）。
- **MLA 不适配**。

### ClusterKV
- `accuracy/` 摘取 + Qwen3Attention 移植；依赖钉版 torch2.5/4.45/pylibraft-cu11 →
  **独立 uv venv**（uv.lock+清华镜像）。
- 聚类语义与 cavg/ccluster 族对应 → 预算对齐 K2=1024 臂互证。
- **MLA 侧**：语义簇思路理论上可迁移到 MLA rope/nope 分离表示（对 nope latent 聚类），
  作 TLI-MLA 的对照候选；官方无 MLA 实现，属方法侧扩展后的公平对比。

### DSA（2026-10-11 用户追加）
- 定位：训练型轻量 MLP 直接预测 topk 位置（training-aware，训练换推理速度），与
  Quest/TLI（推理时 qk score 选 chunk）本质不同。
- **复现性评估（阶段 0/1 待办）**：官方开源（arXiv 2504.15534，LLM-R 权重）——查
  是否支持 Qwen3-8B / DeepSeek-V2-Lite-Chat；支持则 B 轨 vendor 复现 + sanity 对照
  （其报告结论：topk=256 时相对 fullkv 近无损、稀疏加速），不支持则 T3 注记。
- 主表措辞：TLI 零训练 vs DSA 需训练阶段 → I4 training-free 卖点对位。

## 4. TLI-MLA 方法扩展（为 DeepSeek-V2-Lite-Chat）

- MLA：KV 压 latent（nope 位置无关）+ rope 部分。TLI 扩展：near/far 分区对 rope key 与
  nope latent 分别索引/聚类，细筛保留 rope 精确分与 latent 表示。
- 与 vendor 复现并行；DeepSeek 档 = TLI-MLA vs（可适配基线复现 / 不可适配者论文引用+注记）。

## 6. Sanity 对拍硬门禁（用户 18:5X 强调）

- 每个 vendor 臂先跑官方已报数字（近官方模型）→ 偏差在任务噪声内才允许全量。
- **数据趋势必须与官方结论一致**：如 Quest 在 LB 相对 fullkv 的掉点幅度、
  MoBA training-free 明显掉点（训练依赖）、ClusterKV 近无损趋势。
- 若我们跑出的数与官方结论矛盾（如稀疏方法比 fullkv 还高而官方是掉点）→
  **停表反思**实现/预算/打分口径，排查后复测；门禁不过不进论文表。
- 结论记录在 task_details（差异表 + 排查结论）。
