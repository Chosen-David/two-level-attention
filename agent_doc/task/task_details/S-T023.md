## 复现思路（三基线 × 三模型的关键难点）

### Quest（mit-han-lab）
- 官方 `evaluation/quest_attention.py` 只 monkeypatch Llama/MistralAttention → 写
  `qwen3_quest_patch.py` 移植到 Qwen3Attention（字段 `layer_idx/num_key_value_groups/
  head_dim` 均存在，工作量小）；超参对齐 token_budget=1024 / chunk_size=16。
- kernel 线依赖 libraft（子模块缺失，网络受限）→ 精度用纯 PyTorch 路径；
  性能数字引用官方论文 + 平台差注记（降级方案已批）。
- **MLA 不适配**：Quest 的 GQA 逐维 minmax/query 符号假设在 DeepSeek-V2 上不适用
  → 该档用论文引用数字 + 口径说明，或不出 Quest 列改注记。

### MoBA（MoonshotAI）
- `moba/` 4 文件，`register_moba(MoBAConfig)` 注册 backend，prefill 走
  `moba_attn_varlen`；预算对齐 topk = budget_token / chunk_size（chunk=64,
  topk=16/32，与 E89 臂口径一致以便互证）。
- **training-free 下界对照**：官方自述需续训，非 drop-in；training-free 跑官方码
  精度低于论文值属预期，论文措辞「MoBA 为训练依赖方法，我们在 training-free 设定
  下以其官方实现复现作下界对照」。
- decode paged attn 官方 TODO → 长生成任务走慢速路径（对方工程债，不改）。
- **MLA 不适配**：同上，GQA 假设。

### ClusterKV（sjtu-zhao-lab）
- `accuracy/` 摘取 + Qwen3Attention 移植（官方支持 llama/glm4）；依赖钉版
  torch2.5/transformers4.45/pylibraft-cu11 → **独立 uv venv**（自带 uv.lock+清华镜像）。
- 聚类语义与我们的 cavg/ccluster 方法族对应 → 预算口径对齐 K2=1024 臂以便互证。
- **MLA 侧**：ClusterKV 是语义簇召回思路，理论上可迁移到 MLA 的 rope/nope 分离表示
  （对 nope latent 聚类），作为「TLI-MLA 扩展」的对照候选——但官方无 MLA 实现，
  属我们方法侧扩展后的公平对比（见下）。

### 方法侧扩展（TLI-MLA，为 DeepSeek-V2-Lite-Chat 做准备）
- DeepSeek-V2 MLA：KV 压成 latent（nope 位置无关）+ rope 部分。TLI 两级索引要扩展到
  该结构：near/far 分区对 rope key 与 nope latent 分别索引/聚类，细筛保留 rope 精确分
  与 latent 表示。
- 这是**方法侧**工作（TLI 支持 MLA），与 vendor 基线复现并行推进；最终论文的
  DeepSeek 档 = TLI-MLA vs（可适配基线的复现 / 不可适配基线的论文引用+注记）。
