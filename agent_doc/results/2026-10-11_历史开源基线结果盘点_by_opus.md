## 0. 先回答"哪些能进论文、哪些不能"

**TIA / TWI 不是第三方论文的官方复现，没有外部论文锚点，不能当开源 baseline 写进论文对比表**：

- `tia` = TIAIndexer（`sparse_attn/indexer/tia_indexer.py`）——**本库自家前代方法**，
  两级 topk 索引的直系祖先（tia_64_128_1024 预算结构与现 TLI 同构）。论文里
  只能作为内部 ancestor/消融对照出现，须显式标注"ours (predecessor)"；
- `twi` = TwilightIndexer（`sparse_attn/indexer/twi_indexer.py`）——本库内部
  实现的 per-token 4bit min-max 量化上界 + sim 0.95 贪心去重选择器，
  命名 "Twilight" 若要对应公开工作须先考证；无锚点前不进对比表。

**有论文锚点、可进对比表**（当年都是算法语义复现、非 vendor 官方代码）：
Quest（mit-han-lab）、MoBA（MoonshotAI）、SnapKV、H2O、PyramidKV、
StreamingLLM。DeepSeek 现在做的 vendor 官方代码接入（`exp/vendor_baselines/
quest_vendor/`，21:51 我看到了你的 README）是更强的证据形态，以下历史数据
供你交叉参考与避坑。

## 3. Quest 是怎么接的（给你的避坑经验）

`sparse_attn/indexer/quest_indexer.py`，纯算法语义复现：

- **页上界**：`prepare_index` 按页（block_size，quest_64_16 = 页 64 ×
  选中 16 页 = 1024 token 有效预算，与 TLI K2 对齐）算 k_min/k_max；
- **页打分**：q·k_min 与 q·k_max 取 max 后逐维求和（论文 §3.2 口径），
  **GQA 处理是组内 mean 聚合**（`rearrange('(h g) tk -> h g tk').mean(-2)`）
  ——注意 GQA 聚合粒度是审稿敏感点：GPT phase_matched advice §6 点过
  SparQ 主库与 gpt-fast 移植的 GQA 粒度差异，你 vendor Quest 时按
  官方库 01c1623b 的粒度对齐，不要默认沿用我这个复现的 mean 聚合；
- **选择**：页级 topk 后页内全选（HF eager 参考路径：全前缀算完再
  施加 mask）——**只能作质量参考，不能据 selected 数宣称稀疏提速**
  （GPT phase_matched advice §3 语义门禁，对 Quest 论文 §4.3.2 的
  E2E 口径也是这一条：那是单 token decode 平均延迟，不是完整请求）。

预算档覆盖（预测文件都在，可直接重打分）：

- Qwen3-8B：`exp/results_longbench/Qwen3-8B/pred_{512,1024,2048}/`
  quest_64_{8,16,32} / tia / twi / none 全套；
- Qwen3-14B、Qwen3-32B：同结构同臂覆盖（含 32K+ 长档）；
- MoBA：`exp/results_longbench/Qwen3-8B/e89_moba/pred_moba/`（文件名
  `*-tli_64_128_1024_c4_A-moba.jsonl`，借用 TLI 管道的 MoBA 语义臂）。

## 4. 口径警告（复用前必读）

1. **全部是旧口径**：E121 修复（R01 BOS-aware 裁剪 / B04 首 token EOS
   判停 / B10 near 左界）合入**前**生成，生成协议与现在 E125/E116b
   新口径不同。可作方法间**相对排序**的历史先验，**不可与任何新口径
   表直接横比混池**。
2. **身份侧车缺**：E76 manifest 协议（treatment canonical manifest + _h 哈希）
   之前的老文件没有 `.tli_manifest.json` 侧车，身份只能靠文件名+md5
   溯源，`results/README.md` 的状态约定里这类属 `usable-with-scope`。
3. **重新打分便宜**：difflib scorer 可直接对上述 jsonl 重评
   （`python3 -m benchmark.LongBench.eval`，模块方式跑），如你需要
   新口径对齐的 baseline 分数，走你的 vendor 官方接入 + 新协议重跑
   更干净，历史数据当 sanity 交叉参照。

## 6. 测试链路与可信度评估材料（用户 22:1X 指令补：如实描述怎么测的）

### 6.1 统一生成协议（方法间可比性的根基）

所有臂（none/quest/tia/twi/tli/moba）走**同一个生成入口**
`benchmark/LongBench/pred.py`（CLI `python -u -m benchmark.LongBench.pred
--model Qwen3-8B --task <T> --method <quest|tia|twi|tli|none> ...`）：
同一 prompt 模板、同一截断规则、同一生成参数（--e 0 温度 0 贪心）、
同一 LongBench 官方数据（`benchmark/LongBench/data/`，行序 _id 绑定）、
同一 difflib 打分（`python3 -m benchmark.LongBench.eval`，模块方式）。
方法差异只发生在 attention 层 mask 的选择上——这是 §1 表内横向可比
的原因。注意旧口径警告（§4）：BOS 裁剪/EOS 判停协议是 E121 之前的
版本，对所有臂一致，故表内排序仍有效。

### 6.2 接入层代码（当前树内可核验）

- **Indexer 抽象基类**：`sparse_attn/indexer/base.py`（prepare_index /
  compute_score / compute_mask 三接口）；
- **注册表**：`sparse_attn/indexer/__init__.py` 的 `indexer_type_dict`
  （quest/tia/twi/tli 四 indexer 类）；
- **QuestIndexer**：`sparse_attn/indexer/quest_indexer.py`（全文 81 行，
  §3 已逐段描述，可直接读源核验算法语义）；
- **TwilightIndexer（TWI）**：`sparse_attn/indexer/twi_indexer.py`；
- **TIAIndexer**：`sparse_attn/indexer/tia_indexer.py`（自家前代）；
- **MoBA 臂**：非独立 indexer，是 TLI 框架内的 `_moba_mask` 路径
  （`sparse_attn/indexer/tli_indexer.py`，chunk 分区+gate 语义复现，
  075 修复时曾同步修过其 padded-S 缺陷——同缺陷同修）；
- **attention 挂载**：`sparse_attn/patches/qwen3_attn_patch.py`
  register_patch——HF eager 参考路径：**全前缀 QK/AV 计算完成后施加
  选择 mask**，故全部质量数据是"选择质量"口径，不含任何稀疏提速主张。
