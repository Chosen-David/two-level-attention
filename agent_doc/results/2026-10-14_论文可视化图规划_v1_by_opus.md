结合已落袋数据资产（E109/E123-E138 全链判决 JSON）逐图规划：**每图给出

叙事总框架（**E139 wall 判决后 v1.1 修正口径**）：**decode 主线（质量 CI
含 0 三重判决 + 5.47× 稳态）+ prefill dense 生产口径；稀疏 prefill 降级
为质量-粒度-预算分析对象**（abl-5 消融/limitation 段），性能列如实标净负。

mask 实现（644ms），非 dense——vs dense SDPA（e2e 生产 dense 口径，

这不是退让，是 serving 指标的正确讲法（TPOT/吞吐/decode 稳态，Quest

## 一、Observation 组（引出三个创新点）

### obs-1：注意力质量的距离衰减 + 分割线（引出 near/far 分区）

- **叙事**：token 重要性随距离衰减——过了某分割线后「潜在重要 token 密度」
  骤降，near 区（近期 + 密集）必须细保、far 区（远期 + 稀疏命中）可以
  粗筛 topk。这就是 near/far 分区不是拍脑袋的来源。
- **数据来源**：**待采集**（observation 性质，需跑一次 dense attention
  的逐距离桶 atten mass 统计）。可复用 E135a 的采集 harness
  （`e135a_sinkswa_only` 臂的 mask/mass 采集链路，改距离桶聚合）。
  参照 ClusterKV 的 Fig.2 形式。
- **图形式**：x=距 query 的 token 距离（log 轴），y=累计 atten mass /
  每 token 平均 mass；画一条分割线（near_L 动态位置），标注线两侧
  mass 占比（near ~X% vs far ~Y%）。多任务多条曲线（hotpot/musique/
  gov_report 各一条）。
- **注意**：swa+sink 观察按 guide 要求并入本图左端（sink 128 + swa 128
  两段强制区的 mass 占比单独标出——它解释为什么强制区不进粗筛）。

### obs-2：near/far 的层间 atten mass 分布（引出 D' gate）

- **叙事**：选部分层（near 聚集、far 极稀疏 mass 极低的层），far 区可整
  层跳过——论文表述「跳过的 far 区只占 X% atten mass」。
- **数据来源**：**部分已落袋**——E137 自校验
  `e137_calib_256_selfcheck.json`（τ=0.05 割 30/576 层 5%、τ=0.10 割
  115/576 20%，层集 {L7,L8,L10,L11,L35}）+ E129/E138③ e2e 零成本判决
  （`e137_dyn_dgate_verdict.json`、`e138_dgate_sub_e2e_verdict.json`，
  CI 均含 0）。层 atten mass 逐层抓取曲线需补一次全层采集（E137 只记了
  触发层）。
- **图形式**：x=层号（0-35），y=每层 far 区 atten mass 占比；低于阈值
  的层用高亮标记（「可跳层」），旁注跳层集合的 e2e Δ=+0.04 CI 含 0。

### obs-3：低频子空间的判别力（引出 tail32 子空间）

- **叙事**：FASA 口径——注意力判别信号集中在低频段（tail 子空间），
  高频段对 topk 排序贡献可忽略 → 粗筛只在 32 维上做。
- **数据来源**：**已落袋**——E133 mask 对拍 98.34%
  （`e133_subspace_verdict.json`：单键差 L1 128→32 后 mask 逐位一致率，
  24/24 步有差异 ~1.66%/步）+ E133 e2e -0.32（CI 上界贴 0，噪声级）。
  参考做法：对若干层的 q/k 做 DCT，画每频率段的 topk 选择集 Jaccard
  相似度 vs 维度预算（128/64/32/16）——16/32/64 维对比数据按 ablation
  guide 要求补采集（见 abl-2）。
- **图形式**：x=粗筛维度（16/32/64/128），y=与 full-128 的 mask/topk
  一致率（Jaccard 或逐位一致率）；32 处标注「4× 省算、98.34% 一致」。

## 二、Evaluation 组（主表 + 延迟）

### eval-1：质量主表（三件套）

- **数据来源**：**已落袋**——E109/E116b 三件套（LB v1 13 任务、LB v2
  503 题、RULER 32K/64K/128K，mavg 冠军 47.49~47.91 各档，fullKV 锚点
  46.43~47.91）。模型规模轴 Qwen3-8B 已齐；**Qwen3-32B 与 Llama 待跑**
  （guide 要求，GPU 窗口排队）。
- **形式**：大表（任务×方法），TLI vs HISA/Quest/FA/FFD 基线——基线数字
  走 `2026-10-11_历史开源基线结果盘点_by_opus.md`（usable-with-scope，
  标注口径）。**注意 E138 判决后主表口径 = decode 稀疏 + prefill dense
  （PFDD 臂）**——已落袋 `e138_abl_sub_e2e_verdict.json` ①臂分数，但
  ①臂是五任务子集，主表三件套须按 PFDD 口径重跑（待 GPU）。
- **延迟口径**：guide 问「prefill 和 decode 分别加速多少」——答：decode
  稳态 5.47×/4.76× wall（E127）为主张；prefill 侧如实报稀疏 vs dense SDPA
  净负（`e139_k2_prefill_wall_verdict.json`：grp64@32K 0.10x）+ 稀疏路径
  内部实现优化 3.82x（`e138bc_prefill_wall_bench_verdict.json`，mask→
  gather+预取，标注分母口径防误读）+ 各基线对应数字（HISA/Quest
  各自 github 复测，待窗口）。

### eval-2：延迟图（decode 主叙事）

- **数据来源**：**已落袋**——E127 稳态 8.29→1.52ms/步（S=64K，36 层）；
  E131/E134 优化链（-8.5~-19.8%）；E139 wall 判决（grp64 稀疏 prefill vs
  dense SDPA 净负 0.10x@32K + K2 扫参 512→2048 +46% + chunk-shared
  0.60x 对照 + 机器锚定）。
- **图形式**：双 panel：(a) decode 稳态延迟 vs 序列长度（TLI vs
  fullKV/Quest，log-y）——**唯一加速主张图**；(b) prefill wall 绝对值
  vs 长度（dense SDPA vs chunk-shared vs grp64 各 K2 档，sparse/dense
  比值轴如实呈现全档 <1——prefill 稀疏性能边界诚实入图，进 limitation）。
  e138bc 的 3.82x 若入图须以「稀疏路径实现优化」单独标注，不得与
  vs-dense 加速比同轴混排。
- **端到端账**（服务口径，TTFT/TPOT）：**待采集一轮**——prefill dense
  + decode 稀疏的实际 TTFT/TPOT/end-to-end 对照表（long output 场景
  decode 收益占 >90% 时间，这是 decode-only 故事的量化锚点）。

### eval-3：召回预算 Pareto（对标竞品召回数）

- **数据来源**：**待跑**（任务 #245 E139）——K2∈{1024,768,512,384,256}

## 三、Ablation 组（guide 的 fig1-4）

### abl-1（fig1）：海选冠军证伪 + 参数网格通用性

- **数据来源**：**已落袋**——`results/各个method组合配置冠军的海选表现.md`
  （E125 四臂海选 + E130/E123 网格）。
- **形式**：(a) 各 method 组合的海选分数条形图（mavg 47.91 冠军，
  cclustersim 48.25 点估计更高但 CI 含 0——如实标注，E128 pairwise CI
  全表）；(b) best 网格 (α,β,γ)=(.25,.125,.625) 在 LB 子任务上的分数
  热力图 vs 每任务各自最优网格的差距（证明通用性）。
- **注意**：cclustersim 进消融非主线（E128 判决口径），图注必须引
  pairwise CI 表。

### abl-2（fig2）：低频子空间消融

- **数据来源**：**部分已落袋**——E133/E133b/E133c 链（tail 32 质量噪声
  级 + 性能三臂 -8.5~-19.8%，`e134_perf_reverdict.json`）。**16/64 维
  与 高频/random 频对照组待跑**（guide 明确要求三对照）。
- **形式**：(a) 维度扫描 {16,32,64,128} × 质量分数；(b) 频段对照
  {tail,head,random} × 质量；(c) 子空间单独提速（E134 三臂数据：
  prepare_index -36%、compute_score -14%）。
- **审稿人问题预备**（guide 原话「为什么不测 prefill 和 decode 都开」）：
  E138 ①② 双稀疏已测（-5.77/-4.90 判决落袋）——如实放进 limitation/
  trade-off 表，与子空间消融分开放。

### abl-3（fig3）：D' gate 消融

- **数据来源**：**已落袋**——E137（eps0.05 Δ-0.03 CI 含 0）+ E138③
  sub/sub 复证（Δ+0.04 CI 含 0）+ E137 层集统计（5%/20% 层可跳）+
  单独提速（跳层省 far 细筛算，E127 口径下的 far 段占比可算出）。
- **形式**：(a) 开/关 gate 的质量（5 任务 bar + CI）；(b) 每层 far
  atten mass 曲线标跳层集（复用 obs-2 数据）；(c) gate 单独提速 bar。

### abl-4（fig4）：middle 区有效性（排除 sink+swa 解释）

- **数据来源**：**已落袋**——E135a `e135a_sinkswa_only` 归因臂（纯
  sink+swa mask indexer 旁路 vs 完整 TLI 的 e2e 差距）。
- **形式**：三柱对照：full TLI vs sink+swa only vs fullKV——middle
  区贡献 = TLI − sinkswa_only 的分差，按任务分柱。

### abl-5（新增，E138 粒度曲线）：稀疏 prefill 质量-成本 Pareto

- **数据来源**：**今日收官在飞**（17:47 收割）——E138 粒度曲线
  c2048→c64 + grp64/grp256 组版（`e138_chunk_granularity_verdict.json`
  链，已落袋 c512/c256/c128，c64/grp64 ETA 今日 17:40）。
- **形式**：x=选择粒度（chunk/G），y=hotpot & musique 分数，dense 锚点
  水平线；第二轴放 prefill wall **绝对值/净负比值**（dense 100ms /
  chunk-shared 168.6ms 0.60x / grp64 981ms 0.10x，E139 wall 判决）+
  K2 预算轴（1024→2048 质量 -3.4→-0.7 买回但 wall 再 +22%）——
  粒度-预算-质量-性能四轴 trade-off 表。**这是 limitation 段的量化
  支柱**：稀疏 prefill 质量可救（grp64+K2048 ≈ dense）但性能全档
  净负，粒度细化的性能代价 = 选择链 ×32 + W 并集变宽（5.8x）。
