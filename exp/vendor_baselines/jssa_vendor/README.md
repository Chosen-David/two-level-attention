# JSSA official source and portable environment candidate

Official source: https://github.com/jiwonsong-dev/JSSA at **34ce5abd82453b16ca6d5f16a1a8ae50fac5b920**. All 18 tracked upstream files are archived byte-for-byte in `upstream/`, including original README, install script, images and MIT LICENSE; no `.git`, virtualenv, model, basis or machine secrets. `UPSTREAM.json` binds every original file and the pinned vLLM metadata by SHA256. Upstream's main `jssa_vllm.patch` is Apache-2.0 (vLLM-derived); full Apache license is `environment/vllm_metadata/LICENSE`. The small DeepGEMM/FlashMLA patches retain upstream MIT attribution. These sources are archived, not installed or registered as a new project benchmark method.

## Safe default and environment boundary

Run `python3 environment/manage.py --check` or `bash environment/provision.sh` from this directory. Both only check local bytes and print a plan; no pip, network, GPU imports, model loading, data collection or system modifications. `provision.sh --check` omits printed installation guidance. Unsupported execution flags fail. The printed recipe requires explicit host-side review; it stops before installation and contains no calibration/benchmark launch. It never invokes upstream setup's MLA cache-removal branch.

`environment/source-lock.json` pins **sources and known requirements**, not a fully resolved environment lock. Original vLLM requirements/pyproject/setup are preserved in `environment/vllm_metadata/`. Requirements include ranges, upstream supplies no lock, and wheel/transitive hashes are unresolved. Do not call this a working installed `.venv` or reproducible binary environment. On an authorized idle host, resolve and hash every wheel/dependency, retain pip report/freeze, driver/toolchain identity, and run acceptance before sharing a completed lock. Do not commit actual `.venv` binaries or host paths.

- Dedicated Python **3.12** env; separate from existing paper/baseline transformers4.57 environment.
- Required vLLM revision **39910f2b25aacc09f5e7f166cdf0030b19f8b9e8**, distinct from JSSA HEAD. Precompiled wheel must match this revision. Choose `VLLM_PRECOMPILED_WHEEL_VARIANT=cu130` or `cu129` explicitly; do not rely on README's default claim versus install autodetection.
- Pinned vLLM CUDA requirements: torch/torchaudio2.11.0, torchvision0.26.0; other exact pins and ranges remain in original files. Runtime Triton compilation still matters despite no native build in the precompiled GQA route. CUDA driver, wheel availability/hash, compiler/Triton compatibility remain unverified here. No nvcc/driver/GPU capability acceptance is claimed.
- Calibration README specifies transformers5.8.0 with unpinned datasets/accelerate. Its default `--attn_impl flash_attention_2` needs a validated FA2 implementation: `flash-attn` or the documented optional Hugging Face `kernels` fallback route in transformers5.8.0. Neither dependency is explicitly specified upstream; the implementation/version/build remains unresolved. Resolve and test the chosen route explicitly. Choosing `--attn_impl sdpa` is a deliberate alternative with its own recorded identity, not a silent substitute.
- Upstream README Qwen3-8B calibration lacks `--yarn`, whereas throughput code supplies YaRN4 for default-RoPE Qwen3. Freeze/check **effective calibration and serving RoPE**, checkpoint/tokenizer hashes, producer revision, calibration data/sample IDs and basis hash before any launch. Basis `{'M': ...}` alone proves none of these; execution stays blocked without matching provenance. No README calibration/benchmark command is presented as validated.
- Calibration-input provenance: paper Appendix A.4 describes center-cropping the packed sequence to131072 tokens, while this archived `tokenize_truncate` keeps first/last halves, decodes and re-tokenizes them; the final token count is not strictly enforced. The package preserves that official code path unchanged. Do not claim paper-input identity without an actual calibration receipt recording data/sample IDs, tokenization/cropping and resulting lengths.
- Upstream calibration model-family and throughput YaRN dispatch inspect the model-path substring `qwen3`; a bare snapshot/hash path can fall back to Llama handling or omit YaRN. Preflight must compare the explicit path identity with config `model_type` and effective RoPE. Do not silently rename paths or rewrite upstream dispatch; unresolved disagreement blocks execution.
- Actual core patch behavior: all-prefill batches are dense; otherwise, for basis-bearing non-sliding-window layers, one-token decode rows use the sparse path and prefill rows remain dense. Layers without a basis and sliding-window layers remain dense. This corrects the upstream README's blanket mixed-batch wording. Gather-free attention additionally requires supported dispatch conditions (including power-of-two GQA group size); Qwen3-8B G=4 is eligible, whereas Qwen3-14B G=5 falls back to gather-then-attend. Eligibility is not measured runtime acceptance, and the remaining conditions still apply.
- GQA source says compute capability>=8.0; paper B200 throughput is not portability acceptance. MLA patches/builds/cache clearing are archived only, excluded from this bounded provisioning task. No new MLA research, model matrix or FFD Qwen port.

They do not import vLLM, compile Triton or establish task accuracy/GPU performance.
