## 需修复的技术问题（4 项，优先级高）

### C: LongBench prefill_frozen_skip.py decode 循环缺 metadata 准备及 commit

**现状**：
- `prefill_frozen_skip.py` 的 `generate()` decode 循环直接对 `GraphReadyPagedRegionCache` 反复调 `model()`，**循环内没有任何 `new_step`/`plan_common`/`prepare_metadata`/`commit_step` 调用**
- 完整生命周期只存在于 `GraphRunner.step()`（graph_runner.py L120-166），本文件未接入
- 后果：`state.logical_length` 永不推进 → block table 不扩展 → RoPE 位置错误 → KV 写入 slot 错误

**附带发现**：
- 默认 `--attention sdpa` 臂在当前架构下连 prefill 都崩溃（`GraphReadyPagedRegionCache` 无 `update()` 方法）
- `pred_frozen_static_gate.py` 已有完整生命周期（但仅 GLM + 静态 gate）

**修复方向**：
- 方案 1：将 `prefill_frozen_skip.py` 迁移到 `decode_frozen_request`（GraphRunner 路径）
- 方案 2：标记 `prefill_frozen_skip.py` 为 deprecated，统一走 `pred_frozen_static_gate.py`
- 需要支持 Qwen3 的 LBv2 NFA 入口

### G: GLM RULER 四态区域跳过未启用

**现状**：
- `pred_ruler.py` L196-198：GLM NFA 分支硬编码 `GateConfig(mode='full')`
- `mode='full'` → `decide_regions` 中 `skip_near=False, skip_far=False` 恒成立
- 同时强制 `nfa_enable_layer_skip=False`、`nfa_dyn_dgate=False`
- 四态机制（sink/swa/near/far）在共享 `GraphReadyPagedRegionCache` 中存在且支持逐层 skip，但 GLM 入口未启用

**修复方向**：
- 解除 GLM 的 `mode='full'` 限制，允许 `mode='dual'`（或按 gate 标定结果选择 near/far/dual）
- 需要验证 GLM 四态跳过与 Qwen3 的语义一致性
- GLM patch（glm4_moe_lite_attn_patch.py）本身是纯执行器，skip 决策由 frozen_runner 的 gate 标定 + cache 层消费

### J: 选择器 query 时序 — 消费上一步 query

**现状**：
- `nfa_layer_batch_selector.py` docstring 明确："Both read **previous-step queries** from `_last_q_buf`"
- `record_query` 在 decode forward 内把本步 query 写入 `_last_q_buf`，供下一步使用
- 所有层选择在 model forward 前完成（graph_runner.py L130-140），层内只消费预选好的 gather indices
- 与论文"当前 query 筛选"不一致（存在一步滞后）

**根因**：CUDA Graph 静态形状的工程折衷——graph replay 前必须完成选择，无法等层内当前 query

**修复方向**：
- 方案 1：论文口径修正——明确写"previous-step query selection"（与 MInference 等方法一致）
- 方案 2：eager 路径改为层内当前 query 选择（牺牲 graph 兼容性）
- 方案 3：两阶段选择——forward 前用上一 query 粗筛，层内用当前 query 精筛

### K: 共享物理页分配 — keep 层抵消 skip 层回收收益

**现状**：
- 物理存储 per-layer（每层独立 arena），但页号/分配决策全局共享
- `_alloc_pages` 从 layers[0] 弹出 id 后强制其余各层弹同一 id（不一致直接 RuntimeError）
- `_batch_reclaim` 按"全层并集"回收：只要一个 keep 层需要某区域，该页在所有层保留
- GLM RULER mode='full' 下回收收益为 0

**修复方向**：
- 方案 1：逐层独立页管理（每层独立页表 + 独立分配/回收）
- 方案 2：兼容组页管理（按 skip 策略分组，同组共享页表）
- 需要评估逐层管理对 graph 静态形状的影响

## 口径偏差（3 项，需论文注明）

### D: LongBench prompt 截断口径分叉

- `pred.py`（旧入口）：material 全量 prefill + question 后缀逐 token 输入（与 Quest 官方一致，100 字符仅是切分边界）
- 新入口（prefill_frozen_skip / pred_frozen_static_gate）：全量单次 prefill，无逐 token 后缀
- **两条链路非同口径**，论文须注明或对拍

### F: RULER 生成语义偏差

- MAX_GEN=64 统一（与 KVCache-Factory 一致），但官方 lm_eval per-task 不同（niah 128/cwe 120/fwe 50/vt 30）
- cwe 官方给 120 token，本仓 64 可能截断
- 换行停止是本仓自定义，官方无此机制
- 首 EOS 处理：等效 min 2 token，与 HF min_length 抑制式有差异

### I: RULER 64K/128K 数据来源

- 64K/128K 是 32K 源的 needle 保真循环扩展（`gen_ruler_long.py`）
- 与官方从零合成协议在 needle/干扰词多样性上有结构性差异
- 论文中应注明"64K/128K 为 32K 确定性扩展"口径
