## 1. 论文核心贡献（三轴协同设计）

### 1.1 创新一：Content-Aware Scanning via 2-bit Quantization

**问题**：现有稀疏 attention 的"Selector-Computer"解耦范式——selector 先过滤索引，computer 再取数据计算。computer **无法复用 selector 的中间计算**，效率低。同时 metadata（mean vectors、min-max bounds）需要额外存储且有信息损失。

**方案**：将 K cache 拆成两部分：
- **k_quant**：2-bit 量化缩略图（用于高吞吐扫描阶段）
- **k_res**：8-bit 残差（用于精细化计算阶段）

**量化方案**：Symmetric Mid-rise（不含零）均匀量化，codebook = {-1.5, -0.5, +0.5, +1.5}。
**关键洞察**：标准含零 codebook {-1, 0, 1} 只用到 3 个状态（log₂3 ≈ 1.58 bit），浪费 20% 表示能力。RoPE 后的 key 不含零，mid-rise 不含零方案保持方向保真度。

**扫描阶段**：用 q · k_quant（2-bit）做粗筛。选中 block 后用 s_final = q·k_quant + q·k_res 做精确计算 ≈ FP16 精度。

**理论保证**：Appendix B 证明量化噪声 e_approx = q·ε/√d 是亚高斯的，假阴性率（漏掉重要 token 的概率）P(False Negative) ≤ exp(-λ²_margin / 2σ²α²)，随安全边界指数衰减。

### 1.2 创新二：Top-δ Selection Strategy

**问题**：top-k（固定预算）不能适应注意力分布变化；top-p（累积概率）需要全局 softmax，有同步瓶颈。

**方案**：保留满足 s_ij ≥ m̃_i − δ 的 token（δ 是相对最大 attention 分数的绝对阈值）。

**关键优势**：
- 无需 softmax（标量比较 vs 全局累积概率）
- 无需排序（向量化掩码 vs radix sort）
- **可并行化**：pseudo-max m̃_i = max(max_sink, max_local) 由 sink token + local token 近似全局 max，每 block 独立计算

**伪最大近似正确性**：Figure 5 显示 86.1% 的层 max 逼近误差 < 0.01。因为 attention 分数主要由 sink tokens 和 local tokens 主导。

**实测开销**（matched keep-ratio ≈ 27.3%）：
| 选择规则 | 每 head 延迟 |
|---|---|
| top-δ | **0.0044 ms** |
| top-k | 0.0090 ms (2× 慢) |
| top-p | 0.1115 ms (25× 慢) |

### 1.3 创新三：Fused Kernel + Full-chain CUDA Graph

**三个 Triton kernel 流水线**：
1. **Pseudo-max estimation**：轻量 kernel，仅用 sink + local tokens 的 2-bit keys
2. **Top-δ selection**：主流 kernel，流式加载 2-bit keys，阈值比较
3. **Fine-grained refinement**：通过 filter 的 block 加载 8-bit residual keys + values

**CUDA Graph 优化**：
- **Block-wise JIT capture**：只在 KV block 数量变化时重新 capture，摊销编译开销
- **Graph-friendly cache**：用 tensor 索引 kernel 替代 Python slicing，全程 device-side
- 99% 的 step 在 CUDA Graph 内执行，仅在 block 边界回退 eager

### 1.4 整体算法流程（Algorithm 1）

```
输入: q_i, K_quant (2-bit), K_res (8-bit), V, δ, sink 集 S_global, local 集 S_local

阶段 1: Pseudo-max 估计
  s_global = max_{j∈S_global} q_i·k_quant_j
  s_local  = max_{j∈S_local}  q_i·k_quant_j
  m̃_i     = max(s_global, s_local)

阶段 2: Top-δ 选择
  I_select = {j | q_i·k_quant_j ≥ m̃_i − δ}

阶段 3: Fine-grained refinement
  s_final = (q_i·k_quant + q_i·k_res) / √d  (仅对 I_select 中的 token)
  output = softmax(s_final) · V[I_select]
```

### 2.5 消融实验核心结论

1. **top-δ vs top-k**：top-δ 同时提升精度（RULER 86.82→90.39）和吞吐（17.4→21.6 tok/s）
2. **2-bit 扫描单独使用无效**（在 top-k 下因排序开销反而降速），但与 top-δ 配合后严格正收益（内存带宽↓）
3. **算法+系统融合放大效应**：fusion 单独在 top-k 下只 1.4×，与 top-δ 配合时 2.2×——"algorithmic and system designs are inseparably linked"
4. **CWE 任务 top-k 严重崩溃**（24.6），top-restore 到 68.2（top-δ 对计数类任务的关键性）

## 3. FFD 方法本质的抽象理解

FFD 的核心哲学可以概括为：

> **"注意力分布本身就包含了稀疏选择的全部信息，只需用低成本方式读取它"**

FFD 的设计逻辑链：
1. attention scores ≈ inner products → 可用量化近似
2. attention 最大值几乎总由 sink+local tokens 贡献 → 可用 pseudo-max 替代全局 max
3. 真实分布中大部分 token 的 score 远低于 max → 固定相对阈值 δ 即可高效过滤
4. 2-bit 扫描的选择结果可直接复用于计算 → selector-computer 融合

**FFD 不做的事**：
- 不训练、不校准
- 不存储 metadata（mean、bounds、indices）
- 不做块级聚合（直接 token 级选择）
- 不需要 sink/swa/near/far 分区

## 4. FFD vs TLI 深度对比

### 4.1 设计哲学对比

| 维度 | FFD | TLI (PSI) |
|---|---|---|
| 核心读取信号 | 2-bit 量化 K 的 attention score | GQA token 级 top-1 score |
| 选择规则 | top-δ（分布自适应绝对阈值） | nl/nt/nb 固定配额几何 |
| 是否需要 metadata | ❌（完全 metadata-free） | ⚠️（swa + ccluster 覆盖标记等） |
| 选择粒度 | token 级 | block 级 coarse + token 级 fine |
| 是否利用 sink/local 结构 | ✅（pseudo-max 计算） | ✅（sink 强制保留 + near 分区远近分离） |
| 是否需分区 | ❌ | ✅（near/far 双池独立策略） |
| 是否需要 top-p/softmax | ❌ | ❌ |
| 是否需要排序 | ❌ | ⚠️（fine topk 需要排序） |
| 自适应性 | 纯局部分布自适应（δ 全局固定） | 远/近分区 + γ 几何自适应 |
| Kernel 实现 | 全融合 CUDA Graph | 候选集 einsum + gather |

### 4.2 理论关系：为什么 TLI 更"保守"

TLI 的固定配额几何 (nl/nt/nb) = 保证最情况下游任务不被"暴击"（总有一个保底的 token 数量池子）。
FFD 的 δ 阈值 = 纯数据驱动的自适应稀疏度。在"正常"文本上效果很好，但可能：
1. 对低熵分布（均匀稀疏上下文）过度丢弃
2. 没有 sink/swa 的显式保证（虽然 pseudo-max 间接利用了 sink）
3. 对 CWE 类任务 top-k 已证实会崩溃（FFD 通过 top-δ 修复）

**诚实地说**，FFD 在 Qwen2.5-7B 上的结果（RULER 85.9/86.9=98.9% 保留率）与 TLI 在 Qwen3-8B（RULER 32K 59.65/59.38≈100.5%）几乎等价。两种方法在"保留全精度"这个指标上都很强。

### 4.3 系统效率对比

| 维度 | FFD | TLI |
|---|---|---|
| 扫描带宽 | 2-bit（极致压缩） | BF16 token 级 score |
| Kernel fusion | selector+computer+graph 全融合 | 候选集 einsum + gather + topk |
| 启动开销 | CUDA Graph 99% step 常驻 | 每步 host launch |
| 块级聚合 | ❌（不做 min/max/mean pooled） | ✅（minmax/avg 块级 coarse） |

## 5. FFD 在 Qwen3-8B 上应用的可行性评估

### 5.1 官方限制
- 建模代码仅 `modeling/llama.py`，不直接支持 Qwen3
- 硬编码 transformers==4.57.3（Llama 专用版本）

### 5.2 但论文已验证 Qwen2.5-7B
- 方法本身不依赖 Llama 特有结构
- 2-bit 量化 + top-δ 完全通用

### 5.3 接入方案分析

**方案 A：在 FFD 官方库新增 Qwen3 modeling（最小改动）**
- 需要从 `modeling/llama.py` 抽出 attention 替换逻辑
- 写 `modeling/qwen3.py`，复用同样的 Triton kernel 和 CUDA Graph 机制
- 改动量估计 ~50-100 行（基本就是 KV 形状的 reshape 适配）
- 约束：需要 `transformers==4.57.3`，但 Qwen3 可能不兼容这个版本 → 需要测试

**方案 B：在 FFD 库直接跑 Llama  checkpoint**
- 直接可用（官方完全支持）
- 但需要 Llama-3.1-8B（或 Llama-2/3）权重
- 好处：结果可直接对比论文 Table 1/2（同模型）
- 问题：我们论文主表基于 Qwen3-8B，跨模型对比说服力弱

**方案 C：将 FFD kernel 移植到我们的 vendor 框架**
- 从 FFD 仓库提取核心 Triton kernel + top-δ 逻辑
- 嵌入我们的 vendor baseline 框架，支持 Qwen3
- 最大化复用论文的量化方案，但需自行维护保养
